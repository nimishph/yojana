yojana: plans as checkable contracts

Plain Markdown plans with an append-only log of every requirement revision. It catches conflicting edits, checks claims against the code, and reads progress from beads.

repo: yojana/epic: yoj-9fesource: docs/design.md

Why #why

Each cntxt-labs tool owns one layer of an agent's working context. Plans are the layer with no owner.

ToolLayerAnswers
bdexecutionwhat to do next
medharuleswhat has proven true
anvesacodewhat the code actually is
yojanaintentwhat we decided, why, and whether the code still agrees

OpenSpec is the closest existing tool. Its specs are living files updated in place by deltas, with git as the history, and archived changes are kept forever. It has no answer for abandoned changes, for two changes editing the same requirement, or for specs that drift from the code. Yojana covers those three.

Principles #principles

  1. Not a VCS. Git versions files. Yojana versions meaning: which requirement changed, from which base revision, in which change, and why.
  2. Requirement-level revisions. Each requirement has a stable id. Each version of its text is a revision: r_ plus 16 hex characters of the sha256 of the normalised text.
  3. The log is the source of truth. Plan files are where you edit; every state rebuilds by folding the log. Same pattern as medha's episode log, duplicated rather than shared until it proves itself in both.
  4. Report, then refuse ambiguity. A conflict or a hand edit on a stale base is reported and refused, never resolved silently.
  5. Markdown is edited, HTML is reviewed. People and agents edit plain Markdown. Review happens in a rendered page with comments and highlights anchored to requirement revisions.

File format #format

Markdown with YAML frontmatter. Requirements are ## headings with an explicit id. Machine-readable parts go in fenced yojana: blocks, which show as code on GitHub and parse without a JavaScript compiler.

---
id: plan/plugin-packaging
status: accepted        # draft | accepted | in-progress | realized | superseded | abandoned
beads: [anv-yp2]
---
## Requirement: plugin loads without a global install {#req-no-global}
The plugin's MCP server starts through npx when anvesa is not on PATH.

```yojana:claim
kind: wql
expression: //file[@path=".claude-plugin/plugin.json"]
expect: true
```

MDX is not an editing format: agents edit it less reliably and it needs a compiler. It may return later as a render-only adapter.

Lifecycle #lifecycle

draft→ accepted→ in-progress→ realized or superseded abandoned

Every transition is an event with an actor and a reason. Progress comes from the linked beads and is never typed in. A change whose beads have not moved for a set number of days shows as stale.

Changes and conflicts #conflicts

A change is a set of deltas (add, modify, remove), each recorded against the revision it started from. Archive applies a change only if every base is still current:

  • an add conflicts if the id already exists;
  • a modify or remove conflicts if the requirement has moved past the delta's base.

The check already exists as findBaseConflicts in yojana-core, with tests.

Store and sync are separate ports, so a remote never becomes a second source of truth.

yojana-store     StorePort backends
yojana-sync      SyncPort adapters

dependency-cruiser enforces a one-way graph, and packages import each other only through src/index.ts.

Keeping files and log in step #sync-files

yojana ingest compares plan files with the last recorded revision of each requirement and records new revisions. A Claude Code PostToolUse hook on edits under plans/ runs it automatically. If a file was edited on top of a stale base, ingest refuses and explains. The file can always be regenerated from the log.

Review surface #review

The HTML renderer turns a plan into a review page: requirements, claim results, bead status and comment threads. A comment is an annotation-added event anchored to a requirement id and revision, optionally with a quoted span. When the requirement gets a new revision, its comments show as outdated instead of vanishing or silently re-attaching.
